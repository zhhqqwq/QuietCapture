# Code of Conduct

QuietCapture contributors are expected to keep project discussion focused, technical, and respectful.

## Expected behavior

- Discuss code, evidence, constraints, and decisions rather than attacking people.
- Give reproducible technical context when reporting problems.
- Accept review based on project scope, architecture boundaries, test evidence, and maintainability.
- Protect private information found in logs, recordings, crash data, or screenshots.
- Stop disruptive behavior when a maintainer asks for a discussion to return to the project topic.

## Unacceptable behavior

Harassment, threats, discriminatory abuse, deliberate disclosure of private information, spam, and repeated disruption of project work are not accepted in project spaces.

## Enforcement

Maintainers may edit or remove project content, close or lock discussions, reject contributions, or restrict participation when behavior interferes with the project or other contributors.

Report conduct problems through a private repository contact channel when possible. Include links or message references needed to review the incident.
